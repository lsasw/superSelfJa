# 团队流程建设标准

> 任务编号：PF-01 / PF-02 / PF-03 / PF-04

## 一、技术 Wiki 写作规范（PF-01）

每条知识点必须包含**四段式**结构：

```
① 问题场景
   这个知识点解决什么问题？在什么情况下会遇到？

② Demo 代码
   最小可运行示例，展示问题复现和解决方案

③ 源码验证
   关键逻辑要引用源码片段，证明不是"猜想"

④ 流程图
   用 draw.io / PlantUML / Mermaid 画出核心流程
```

### 示例模板

```markdown
# ThreadLocal 脏数据问题

## 问题场景
线程池复用线程时，上一个任务设置的 ThreadLocal 
值会被下一个任务读取到，造成数据污染。

## Demo 代码
```java
// 复现代码...
```

## 源码验证
ThreadLocal.ThreadLocalMap 使用开放地址法...
（引用 JDK 源码关键行）

## 流程图
（Mermaid 时序图或 draw.io 截图）
```

## 二、模拟面试制度（PF-02）

```
频率：每两周一次
形式：两人一组交叉面试

面试流程（60 分钟）：
├── 10 分钟 → Java 八股（随机 3 道）
├── 15 分钟 → AI 项目深挖（项目相关追问）
├── 20 分钟 → 系统设计题（抽一道）
├── 10 分钟 → 面试官反馈
└── 5 分钟  → 录屏回放复盘

题目来源：团队题库
评分维度：
  - 回答深度（30%）
  - 表达清晰度（25%）
  - 系统设计质量（25%）
  - 应变能力（20%）
```

## 三、代码 Review Checklist（PF-03）

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | **并发安全** | 共享变量是否有竞争？锁粒度是否合理？ |
| 2 | **异常处理** | catch 后是否有处理？是否吞掉了关键异常？ |
| 3 | **资源释放** | 连接/流/锁是否在 finally 中释放？ |
| 4 | **空指针** | 外部入参是否判空？Optional 是否正确使用？ |
| 5 | **SQL 性能** | 是否有 N+1 查询？索引是否合理？ |
| 6 | **日志规范** | 关键路径是否有日志？敏感信息是否脱敏？ |
| 7 | **命名规范** | 变量/方法名是否清晰？是否符合团队规范？ |
| 8 | **单一职责** | 方法/类的职责是否单一？是否过长？ |
| 9 | **单元测试** | 核心逻辑是否有测试？边界条件是否覆盖？ |
| 10 | **安全漏洞** | SQL 注入/XSS/敏感信息泄露/权限校验？ |

## 四、技术雷达（PF-04）

每季度更新一次团队技术栈评估：

| 状态 | 含义 | 示例（2026 Q3） |
|------|------|----------------|
| 🟢 **采纳** | 团队已验证，推荐使用 | Spring Boot, LangChain, PG Vector |
| 🔵 **试验** | 正在试点，值得关注 | LangGraph, MCP Gateway, Milvus |
| 🟡 **评估** | 需要进一步调研 | A2A 协议, CrewAI, OpenTelemetry |
| 🔴 **暂缓** | 当前不推荐 | 自研 Agent 框架, 自研向量库 |

### 更新流程

```
① 团队成员提名（前两周）
② 技术评审会（第二周周五）
③ 更新技术雷达文档
④ 全员同步（团队周会）
```
