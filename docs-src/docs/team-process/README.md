# 团队建设

> 从个人能力到团队能力 — Wiki 规范、Code Review、技术雷达和模拟面试制度

技术团队的能力提升不是靠「喊口号」，而是靠可执行的标准和流程。本模块提供经过验证的团队建设方法论。

## 📚 文档列表

- **[流程建设标准](standards.md)** — 四段式 Wiki 规范（背景→方案→验证→参考）、模拟面试制度（每周轮换+评分卡）、10 项 Code Review Checklist、技术雷达四象限分类法、Demo 复现四步走（环境→最小示例→断点调试→扩展）

## 🎯 四大支柱

### 1️⃣ Wiki 规范 — 知识沉淀标准化

```markdown
## 第一段：问题背景（为什么做）
## 第二段：解决方案（怎么做）
## 第三段：验证方法（怎么证明对了）
## 第四段：参考资料（从哪学的）
```

### 2️⃣ Code Review — 代码质量守门员

| # | 检查项 | 说明 |
|---|--------|------|
| 1 | 命名语义化 | 变量名/函数名能否自解释？ |
| 2 | 函数单一职责 | 一个函数只做一件事？ |
| 3 | 边界条件 | null/空集合/并发是否处理？ |
| 4 | 安全性 | SQL注入/XSS/权限校验？ |
| 5 | 可测试性 | 是否方便写单元测试？ |
| 6 | 性能热点 | O(n²)？N+1查询？不必要的循环？ |
| 7 | 错误处理 | 异常捕获还是向上抛？日志级别？ |
| 8 | 注释必要性 | 为什么写注释而不是优化命名？ |
| 9 | DRY 原则 | 是否有重复逻辑可以抽取？ |
| 10 | 可读优先 | 下一个人能在 5 分钟内看懂吗？ |

### 4️⃣ 模拟面试 — 能力快速提升

- **频率**：每周一次，轮流当面试官
- **形式**：45 分钟技术问答 + 15 分钟反馈
- **评分卡**：基础(30%) + 项目经验(25%) + 系统设计(25%) + 软技能(20%)
- **题库来源**：[AI 面试题库](../ai-applications/101-ai-interview-qa.md)
